# Examples

Small, annotated code to copy: per framework, what a hospital-side client must contain and how the server side is built from the library, plus a skeleton for adding a framework. Every example imports the library (`flhub_core`, `adapters.*`) instead of re-implementing it, and runs on one machine without a framework deployment: it starts what it needs on `127.0.0.1`, on free ports in a temporary directory, and removes it at the end.

| Framework | Client example | Server example | Run without a deployment | Tested result | Library code |
|---|---|---|---|---|---|
| NVFlare 2.9.0 | [`client/client.py`](nvflare/client/client.py): the Client API loop around `flhub_core.train` | [`server/relay_job.py`](nvflare/server/relay_job.py): the relay job (`RelayAdapter` pattern); [`server/adapter.py`](nvflare/server/adapter.py): the adapter | `python examples/nvflare/server/run_local.py`: NVFlare's simulator, 3 rounds, equivalence check | 3 rounds, `hashes_equal=True` ([§4](nvflare/README.md#4-tested)) | [`clients/nvflare/`](../clients/nvflare/), [`adapters/nvflare/`](../adapters/nvflare/) |
| vantage6 4.15.2 | [`client/v6_example/`](vantage6/client/v6_example/__init__.py): the algorithm function, with its [image](vantage6/client/Dockerfile) | [`server/run_adapter.py`](vantage6/server/run_adapter.py): the adapter (`BaseAdapter`); [`server/run-config.yaml`](vantage6/server/run-config.yaml) | `python examples/vantage6/client/run_local.py`: vantage6's `MockAlgorithmClient`; `run_adapter.py --check` | weights equal to `flhub_core.train` ([§4](vantage6/README.md#4-tested)) | [`clients/vantage6/`](../clients/vantage6/), [`adapters/vantage6/`](../adapters/vantage6/) |
| Flower 1.39.0 | [`client/client_app.py`](flower/client/client_app.py): a `ClientApp` in one file | [`server/adapter.py`](flower/server/adapter.py): the adapter (`RelayAdapter`); [`server/server_app.py`](flower/server/server_app.py): the relay ServerApp | `python examples/flower/run_local.py`: a local SuperLink and two SuperNodes, 3 rounds, equivalence check | 3 rounds, `hashes_equal=True` ([§4](flower/README.md#4-tested)) | [`clients/flower/`](../clients/flower/), [`adapters/flower/`](../adapters/flower/) |
| a new framework | [`client.py`](new-framework/client.py): the client stub | [`adapter.py`](new-framework/adapter.py) (`BaseAdapter`) and [`relay.py`](new-framework/relay.py) (`RelayAdapter`), on a toy framework | `bash examples/new-framework/check.sh`: the conformance suite against both, 3 rounds, equivalence check | conformance 12 of 13 (13 with a data variant), `hashes_equal=True` ([tested](new-framework/README.md#tested)) | [`adapters/common/`](../adapters/common/) |

Each folder's README lists the files, maps the client to the items of the [client contract](../docs/client-contract.md), marks which lines are the framework's standard pattern and which the hub adds, explains the server structure and settings, and gives the commands and the output of a run in a fresh clone.

**Requirements.** The virtual environment of [getting started](../docs/getting-started.md#install), plus the framework's own packages at the versions of [`deploy/versions.env`](../deploy/versions.env): `nvflare==2.9.0` for NVFlare; `pandas==2.3.3`, `vantage6-algorithm-tools==4.15.2` and `vantage6-client==4.15.2` for vantage6; `flwr==1.39.0` for Flower; nothing more for the new-framework skeleton. Run the commands from the repository root.

**Where to go next.** The framework guides ([NVFlare](../docs/frameworks/nvflare.md), [vantage6](../docs/frameworks/vantage6.md), [Flower](../docs/frameworks/flower.md)) cover deployment next to an existing federation; [adding a framework](../docs/adding-a-framework.md) covers the steps around the skeleton.
