# configs

Run configurations for the orchestrator (`python -m hub.orchestrator run --config …`) and the simulation (`python -m hub.sim --config …`). The schema is documented at the top of [`hub/orchestrator/config.py`](../hub/orchestrator/config.py); how each file maps to a result is in [reproducing results](../docs/reproducing-results.md).

| Path | What |
|---|---|
| `mock-3r.yaml` | 3 rounds against the mock adapter on one machine ([getting started](../docs/getting-started.md)) |
| `final.yaml` | the stage-1 final runs: six sites on three adapters, 30 rounds of FedAvg (`--only nvflare` etc. for the single-framework runs; `hub.sim --mode centralized` for the baseline) |
| `stage2/base.yaml`, `stage2/tuned.yaml` | stage-2 defaults and the tuned aggregator settings; the run files below extend them |
| `stage2/topology.yaml` | which adapter serves which site (the six base sites and the six extra sites of the 12-site test) |
| `stage2/e1/` … `stage2/e7/` | one file per stage-2 final run, named like the run (`s2-e1-dir0.3-fedavg.yaml`) |
| `stage2/s2/`, `stage2/s3/` | the integration test and the tuning grid of stage 2 |
| `stage2/partitions/` | partition manifests: site sizes, label histograms, CSV sha256 and data fingerprints per data variant |
| `dev/` | diagnostics and rehearsals, not final runs |

Stage-1 files (schema 1) list their adapters inline; stage-2 files (`schema: 2`) list sites and take the adapters from the topology. The stage-2 run files are generated by [`scripts/stage2/make_configs.py`](../scripts/stage2/make_configs.py) (`--check` verifies that the committed files are current); edit the generator, not the files.

Adapter URLs point to `127.0.0.1` ports of the reference testbed's central machine, and run directories default to `~/flhub-runtime/runs`. To use a configuration elsewhere, copy it and change `hub_url`, the adapter URLs (or the topology) and `runs_dir`.
